## Runtime boundary and lifecycle

589 uses the existing AbilityAuras scheduler, toggle/output, drain, buffer and buff-dispel paths. Its recipient branch enumerates the existing currently spawned simulacra registry. A recipient must be alive, current for its owner, in the source district and within20m of the source, with both players live/in-world. Own pets qualify; other owners use the exact existing friendly-support predicate: the owner is not a legal PvP opponent of the caster. This is an existing server relationship policy, not proof of every retail friendly/neutral/alliance classification. The ordinary friendly-player path now calls an extracted helper with the identical predicate; its behavior is unchanged.

Each pet's current698 snapshot stores the source/captured activation token, source world/life, recipient world/life, typed values and expiry. A later valid caster replaces the current snapshot. Stopping an earlier caster does not erase a later caster's replacement. Source/recipient death or world changes and replaced/removed pets invalidate stale scores. Toggle-off, unload or leaving range stops new pulses; the final child retains its independent5-second lifetime. Unload immediately stops the parent. Source589 must actually be loaded; ordinary stun/pacify/powerless and cast gates remain in the normal ability path.

Melee and firearms Proxies consume only their matching522/524 channel. Nuker viral attacks and healer healing receive no invented effect. The existing pet base hit curve75+2*level-gap and5..95chance bounds remain explicitly OURS; this patch adds the sourced score to that baseline and does not claim native stat caps. Caster/pet base stats, exact retail combat rolls, multiple simulacra per owner and full pet buff-icon/record presentation remain incomplete.35/697 viral-deflection behavior and unrelated pet aura implementations are unchanged. This is partial execution coverage, not full retail parity.
