## Behavior and transaction boundary

Mission Search reserves each successful item against persisted bag occupancy plus pending mission slots. A container operation defers its nested checkpoints until the outer existing mission mutation commits all ownership and goal state together. A late SQL failure discards staged inventory/nonempty claim/close/goal messages and restores the durable checkpoint. If the original client, character, world, life, district and transport owner is still current and on-world, it then receives exactly one truthful empty8120 to release the pending cursor: zero removed identities and no close. The existing transport fence and world-bound queue suppress obsolete-owner acknowledgements. No other loot owner is consulted. Slot0 is never granted. Unrelated mission actions keep their existing checkpoint behavior.

Before goal callbacks, the selected container state is updated,8120 lists byte-exact claims from its original8119 window, and811a is queued only when fully emptied. Claim/close RPCs precede the goal RPC after committed SQL. The existing transport serializes object sections before RPCs: queue insertion does not guarantee close-before-proxy-despawn wire order. No transport priority barrier is added. Sourced811a closes window29 and clears its cached key independently of proxy view lifetime. Full bags list zero transferred identities, keep the window selected and retryable, and leave the objective pending. The helper unit tests also cover partial/multiple claims and distinct pending slots, but production Open currently lists only the first matching Search item in8119. These helper tests do not establish a complete multi-item production loot-window flow. Repeated Take All cannot replay a completed claim. Item identities retain instance data; they are not replaced by bag slots.
