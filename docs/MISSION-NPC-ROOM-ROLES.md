# NPC room roles across measured mission scenes

Fresh NPC-only phases now derive coverage from the audited scene manifest rather than a sector switch. The first batch covers world 1 sectors 550, 842, 1150 and 1349. The existing 550/1349 payloads are unchanged. Other sectors retain legacy selection until exported and declared; missing/corrupt declared evidence refuses rather than silently using a legacy pose.

After the one ordinary site choice and measured entry, the planner checks the site's actual GO19 markers against original same-floor polygons, reciprocal portals and each required supported wooden door. It prefers the nearest authored room with enough distinct positions for ALL phase roles, including named NPCs and deferred waves. Authored role order and the existing marker ordering within a room remain stable. If no room has capacity, it expands through certified same-floor rooms. Facing variants do not create additional positions. No name, mission ID, arbitrary spacing radius or synthetic offset participates.

Selections persist `RolePlan: 1`. Existing selections without the field keep their original prefix validation and exact restore behavior. The new policy never reallocates fixed or pending actors on restore. Exact selected role, raw marker, standing position, scene route and door evidence remain validated before publication.

The ordinary `mission-npc-interior-route` NativeQa mode now reports RolePlan1. Use normal Missions/Phone offers, ordinary doors and authored interactions. Require partners to occupy distinct certified positions in the selected room or the recorded connected-room expansion. Actual metal Door/Open, wooden passage and native walking remain observed gates; topology alone does not prove clearance. The existing normal route case remains the gameplay regression, with no selected progress/item injection or forced site.

Coverage expansion uses the same exporter over every mission-referenced sector. A Temp-only run is processing the 370 world-1 sectors already covered by elevator evidence. It will retain unavailable resources/ordinals and unsupported portal-door families explicitly. Additional door families require their own original GO class/openability semantics before adoption. World 2 remains a separate resource-completeness pass. Bornmann and other partners receive the same room-capacity policy; there is no per-character placement exception.
