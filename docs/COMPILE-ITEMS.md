## Authority and cleanup

`CompileSession` serializes start, close, validation and executor authority on `ClientData.craftingSync`, shared with both crafting handlers. It snapshots the district and world generation. Every execution rechecks ownership of compiler1271 in the exact slot, loaded969 (including277's grant), in-world/non-LA/alive/noncombat status and ability control gates. A different compiler slot cannot borrow a session. Invalidating the original tool ends it instead of allowing a later replacement request to resurrect it.

Matching native close, another ability request, entering combat, positive health damage, death/control clear and hardline/LA transitions send the linked record off and toggle off once. The view tick checks tool loss, unload and control/world eligibility even without another compile request. A new world clears stale state without replaying the prior world's records. Reconnection creates fresh ClientData. Interruption on another ability request and positive damage is the server's conservative implementation of exclusive/interruptable; exact retail interruption ordering and movement cancellation remain unmeasured. No movement restriction or invented movement-cancel packet is added.

`?compilesession [off]` reports/revokes the actual session only with exact `MXO_DEV_COMMANDS=1`; it cannot grant a tool, load an ability, start a session or compile an item. Existing `?compile` remains a separately gated deterministic QA shortcut; it is not the native activation path.

## Native follow-up source evidence

The same pinned client binary explains the missing Code Bit row. `620827d0..620828ce` scans all 0x208 archive slots. Nonzero entries with the sign bit set and bit `0x04000000` set are skipped (`62082811..25`); this includes every `0x84000000 | GOID << 7 | countMinusOne` stored Code Bit/fragment. Ordinary item codes have no ability/code flags, decode by `(value >> 7) & 0x7ffff` (`62082842..45`), resolve the item prototype and category, then populate rows (`62082a75..62082acd`).
