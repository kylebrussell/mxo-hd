# Windowed client hover and pick offset

Native QA reported that tooltips and accepted picks landed roughly 10–20 pixels below and to the right of the drawn object in a windowed 1024×768 session. Tabs and buttons aligned with the cursor. Windows DPI scaling or a client viewport offset is a plausible cause. The comparison at 100% scaling is pending.

- The client resolves the target before it sends `01 51` (target), `80 c7` (dynamic interaction), or `80 c8` (static interaction). The handlers receive the selected object identity and, for interactions, the requested action. These requests carry no screen coordinates. [Target handler](../hds/world/Client/RpcHandlers/PlayerHandler.cs#L336) · [Static interaction handler](../hds/world/Client/RpcHandlers/ObjectInteractionHandler.cs#L189) · [Dynamic interaction handler](../hds/world/Client/RpcHandlers/ObjectInteractionHandler.cs#L327)
- Mission prop creation sends the GO identity, an optional static binding, and the prop’s world position and orientation. The spawn sends no `HalfExtents` override. A bad pose or asset can affect an individual prop, while this path supplies no shared screen-space offset. [Creation packet](../hds/resources/gameobjects/ObjectManager.cs#L35) · [Mission prop creation](../hds/world/Structures/MissionStaging.cs#L783) · [Mission prop pose](../hds/world/Structures/MissionStaging.cs#L828)
- The native input helper requests per-monitor DPI awareness. Its in-world double click moves the physical cursor before posting the click because the world picker uses the current cursor position. Posted launcher clicks use window-message coordinates. This difference makes cursor handling worth checking in the native client. [DPI handling](../tools/RealClient/Invoke-RealClient.ps1#L94) · [Input paths](../tools/RealClient/Invoke-RealClient.ps1#L180)

For a native comparison, use a shipped static object and a mission prop. At the current Windows scaling and again at 100%, use the same monitor, 1024×768 game resolution, and camera pose for each object. With the physical cursor, record the horizontal and vertical offset from the drawn edge where hover begins, then verify which object the radial selects. If both offsets change together with scaling, prioritize the client viewport and DPI path. If the offset follows only one prop, inspect its pose and model bounds.
