## Protocol and evidence

The driver sends actual8094/8098/809b offer/select/accept requests. It locates the selected site's exact lobby elevator from shipped static rows and persisted lobby coordinates; ambiguous or missing native positions fail closed. Enter/leave uses actual80c8 static-door requests and waits for ordinary committed Ride output when floors differ. Existing QA movement positions the fixture for travel, but no ?missionfloor, forced mission object, source relocation or goal command substitutes for the normal interaction. The legacy master proximity autoexit remains attributed as a limitation; if an authored interaction automatically advances a phase, the raw proof records it rather than calling it an observed ride or full completion.

Every target requires a committed OpenFloor witness and its original raw source identity, Root/Route/Standing/centre/full quaternion. The fixture follows its published route through the existing QA movement helper; actual03 object creation must match that full fixed pose and the actual current-state use must be offered. Each final standing point is independently saved through ?save/2e07 and compared with the exact persisted actor pose; raw movement RPCs/client view sections and save cursors accompany the old source/DTO snapshot. No SQL pose overwrite is used. It sends the actual authored Open/Take use, verifies the current goal tick exactly once and, for Computers, the earned item. Posters require all three ordinary Use ticks and unchanged complete three-object DTO/source set before every interaction. After an interaction, same-phase DTO/site equality is required only if the phase remains current. A legitimate auto-advance instead requires the actual goal acknowledgement/item gain, same mission identity/acceptance, retained earned history and old site-history prefix; raw snapshots retain the old source/DTO and new actual phase. No goal hold or old-phase relabel is introduced.

Initial NPC positions are checked both from the saved checkpoint and actual03 creations, with actual NAV floor and standing height. This is computational pose/floor evidence; actual indoor visual clearance, closed-door access and native use remain Claude-only gates.

No selected success summary/receipt/mission XP is permitted. Wallet checks permit only one real Fortuna kill19204XP in the Merv case and no corpse cash; headless Fortuna uses disclosed weaken1 plus ordinary protocol combat, while native QA requires ordinary combat. No mission rewards are injected or inferred. Raw checkpoints, DTOs, NPC/body attributes, RPC/view cursors, source DLL path/hash/mtime, server PID/output/debug, parser problems and any failed step are written before teardown. The narrow fixture leaves the selected mission active; harness disposal removes its owned schema/server. These are not whole mission progression proofs.
