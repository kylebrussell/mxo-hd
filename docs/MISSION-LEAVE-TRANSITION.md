# Generated mission departure transitions

This is an authored behavior correction for generated sites with distinct mission and lobby elevator floors. It is not a proven universal retail area boundary. Finishing the last goal beside the interior elevator no longer counts as departure. The area-leave dialogue remains, and the phase waits until a committed normal ride reaches that site's matching lobby, an ordinary elevator panel makes the matching floor transition, or the existing far/no-area exception applies. Explicit `leave="0"`, Upload and Escort-to-exit/hardline immediate-completion handling are unchanged. `leave="1"` retains precedence. Authored waypoint `HasLeft`, escort `AtExit`, range, geometry, routes, sources and rewards are unchanged.

Ground-floor generated sites retain their historical proximity policy because they have no distinct floor transition that can establish departure. A new walking boundary is outside this correction. Old checkpoints have no departure evidence and default to absent; they do not acquire evidence from a near-door or lobby pose. An old waiting save at the lobby can use the existing far departure fallback (or return to its mission floor and take the ordinary ride). No distance or wait was introduced into production.

`MissionRideStamp` binds the delayed normal ride to client/data/mission/phase/site, character, district, world/life and transport generation. A cancelled or stale callback cannot teleport or grant departure. Departure is set only after the ride commits its destination. Returning to the mission floor clears it. Ordinary panel selection binds exact shipped panel identities to the uniquely nearest sector panel for each site door, requires the same shaft, distinct source/destination floors and matching panel/door floor-height delta. Same-floor, intermediate-floor and wrong-shaft selections do not grant departure. This binding is a conservative server policy using shipped world coordinates, not newly recovered retail mission-exit code.

The saved departure contains the exact source door and phase; restore accepts it only for the matching current generated site/phase. New phases reset it. The ride and panel mutation use existing mission checkpoint transactions, so SQL failures restore the prior saved departure state and withhold their buffered output. A transport snapshot also restores server Position, selected panel and teleport counter when the checkpoint fails, keeping the failed ride retryable from its original floor. Deferred next-area admission retains departure evidence for a retry.
